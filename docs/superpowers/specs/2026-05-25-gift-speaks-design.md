# Plan: 礼说 / gift-speaks — Claude Skill

## Context（为什么做这件事）

这是用户的第一个 Claude skill 开源项目，灵感来自一个真实的痛点：人在重要时刻想送礼物给亲密关系中的对方（情侣/夫妻/暧昧期），但卡在两件事——「不知道送什么」+「不知道怎么说」。

经过多轮 brainstorming，关键洞察是：

> **真正打动人的不是「金句」，而是「私密细节」。**
> 例：「你是我生命中最重要的人」（AI 味爆表）vs 「上次你说你妈妈年轻时就用这个牌子的香水，我找了三个月」（戳人）

所以产品的真正动作不是"AI 生成情话"，而是：
1. **追问 + 提取**：引导用户回忆和对方的关系碎片
2. **筛选**：从素材里识别出"那个最戳的"
3. **放大**：把它写成对方会哭/会笑/会心动的话

预期成果：一个能在 GitHub 上开源传播、新手能在 1-2 周内做出来的 Claude skill，主打"礼物作为载体，让你被听见、被看见、被信任"。

### 🌟 产品 North Star（最高纲领）

**礼物的目的是增强人与人之间的信任。**

这是 skill 一切功能的最终目的——不是为了"送出更贵的礼物"、不是为了"AI 帮你显得很会送礼"、不是为了"在 GitHub 上拿 star"。**所有设计决策的终极标尺都是这一个问题：**

> **"这件事会增强 TA 对用户的信任，还是会削弱？"**

具体到产品的每个组件，对应关系是：

| skill 组件 | 它建立的是哪种信任 |
|---|---|
| 礼物推荐（戳到 TA 的私密细节） | "你懂我" 的信任 |
| 文案（精准表达情感） | "你在乎我" 的信任 |
| 时机 & 呈现（不打扰、契合 TA 状态） | "你尊重我的节奏" 的信任 |
| 危机场景反提醒（不让用户偷懒用钱解决感情） | "你不糊弄" 的信任（产品对用户）→ 进而"你不糊弄"的信任（用户对 TA） |
| 话术建议（让用户能真诚转述） | "你能真心表达" 的信任 |
| 隐私过滤（不读敏感笔记） | "我可以放心用你" 的信任（用户对产品） |
| 确定性原则（明确推荐度，不模糊推卸） | "你不糊弄我" 的信任（产品对用户） |

**反向应用**：任何一个未来的功能想法，先用 North Star 过一遍——如果它**不能增强信任**（甚至削弱），不做。

## 产品定位（已锁死，不再漂移）

| 维度 | 定义 |
|---|---|
| 名字 | **礼说** / `gift-speaks` |
| Tagline | **「来，让你的礼物为你说话」** |
| 范围 | **亲密关系送礼**（情侣 / 夫妻 / 暧昧期），不预设性别和性取向 |
| 形态 | **Claude skill**（开源 GitHub 项目），不做 Web App、不做独立 App |
| 输入 | 自然语言场景描述 + 可选素材（笔记/日记文件夹路径 或 粘贴文本） |
| 输出 | 3 套「礼物 + 文案 + 时机 + 依据 + 话术」5 字段组合 |
| 语言 | README 三语（中/英/日），skill 内部自动匹配用户语言 |

**反向声明（不做什么）：** 不做礼物电商导购、不做亲情/职场场景、不做多智能体编排、不做日本送礼文化深度适配（MVP 阶段）。

## 核心交互流程：「最多三轮智能对话」+ 迭代

```
🌱 Round 1（必有）：用户描述处境

   skill 精心设计的开场白（详见后文），带 3 个不同情绪基调示例：
     · "下周是我老婆生日，刚搬完家她特别累"
     · "和女朋友冷战三天，因为我忘了她妈手术那天"
     · "她说考研压力很大，我想做点什么"
   用户用一句话说自己的处境。

   AI 同时解析（不预设、从描述中识别）：
     · 关系角色（"老婆/男朋友/伴侣/她/他"等，不预设性别和取向）
     · 时间紧迫度
     · 情绪基调
     · 是否为危机场景（"冷战/吵架/道歉/对不起/出轨"等关键词触发）

🌱 Round 2（按需触发，非固定）：AI 智能追问

   AI 解析 Round 1：信息够吗？
   信息够 → 跳过 Round 2
   信息不够 → 追问 1-2 个最关键缺失，且必须问"触发情感记忆"
              的问题（如"她最近最让你心疼的瞬间是什么？"）
              而不是问卷式问题（"她爱好是什么？"）

   可选轻量追问（不强求，自然嵌入对话，不像问卷）：
     · 预算大致范围（用户不说就用三套方案的价格梯度兜底）
     · 过去 1-2 年送过什么礼物（防止 AI 重复推荐）
     · TA 的 MBTI（知道就说，不知道跳过；绝不单独主动问）

🎯 Round 3（必有）：定位确认

   AI 复述对场景的理解："我理解你的处境是 XX / YY / ZZ，对吗？"
   这一步是"被听见"的灵魂瞬间。
   ⚠️ 若识别为危机场景（道歉/冷战/吵架后），定位环节必须同时
      附带"反提醒"——见下方「错误使用反提醒」章节。
   用户确认后，进入素材检索 + 方案生成。

🔁 Round 4+（迭代，无限次）：方案不满意时调整

   skill 必须支持以下迭代指令：
     · "第二个不喜欢，再换一个" → 单方案替换
     · "整体太贵了 / 太轻了 / 太煽情了，再来一组" → 整组重生成
     · "再加一个 XX 风格的方案" → 增量补充
     · "把第一个的文案改一下" → 局部修改
   迭代时 AI 复用前面的素材分析，不重新追问。
```

**关键设计原则：** 三轮是上限不是固定值。简洁优先。迭代不限次数。

## 素材输入：三档兜底 + 隐私过滤

### 三档输入模式

1. **路径模式**：用户给一个本地文件夹路径（Obsidian vault 或任意笔记目录），skill 用 Read/Glob 检索相关 `.md`/`.txt`
2. **粘贴模式**：用户直接粘贴几段笔记/聊天到对话里
3. **无素材模式**：完全没有素材，skill 仅基于场景描述生成（质量打折，要诚实告诉用户）

### 隐私过滤（路径模式必须支持）

skill 在读用户路径时**不能野蛮地读所有文件**。必须支持三层过滤：

- **按时间窗口过滤**：用户可指定"只读最近 3 个月 / 半年 / 一年"（默认 6 个月）
- **按关键词/人名过滤**：只读包含 TA 名字 / "老婆" / 关键词 X 的笔记
- **明确排除**：用户可指定"不读包含某关键词的笔记"（如前任名字）

### 首次使用隐私提示（强制必有）

第一次进入路径模式时，skill 必须明确告诉用户：

- 读取范围（哪些文件 / 时间窗口 / 关键词）
- 不上传任何内容到云端（仅本地分析）
- 不会输出原文，只输出"提炼后的细节引用"
- 用户可以随时退出或换粘贴模式

### 无素材兜底（绝不编造）

如果用户给了路径但 AI 检索不到任何相关内容（如全是技术笔记），**绝不编造细节**。skill 必须诚实回应：

> "我在你的素材里没找到关于 TA 的具体细节。我可以基于你的场景描述给你方案，但质量会打折——要不要继续，或者你直接粘贴几段你和 TA 的事情给我？"

## 礼物挑选的判断函数（按优先级降序）

AI 在挑选礼物 + 写文案时，必须按以下层级权衡。**越上面权重越高，下层不能压过上层。**

| 优先级 | 因素 | 来源 | 说明 |
|---|---|---|---|
| 1（决定性） | **私密细节** | 用户素材里挖到的具体片段 | 挖到的具体细节永远压倒所有抽象框架 |
| 2（强权重） | **场景信号** | 用户处境描述里的情绪基调和紧迫度 | 生日要喜庆 / 道歉要诚恳 / 慰问要克制 |
| 3（中权重） | **爱的语言**（Gary Chapman 5 种） | AI 从素材+场景里推断 | 见下方"心理学骨架" |
| 4（参考） | **关系阶段** | 用户描述里推断（暧昧期/稳定期/危机期） | 调整礼物分量和文案尺度 |
| 5（兜底加分） | **MBTI** | 用户可选填，不强求 | 提示对方性格倾向，知道更准、不知道也能跑 |

**核心原则：「具体击败抽象」。** 哪怕 MBTI/爱的语言算出来该送 A，但素材里写过 TA 想要 B，就送 B。

### 心理学骨架（prompt 内部嵌入，用户感知不到）

**1. 5 种爱的语言**（Gary Chapman）—— 核心骨架

| 爱的语言类型 | 礼物 / 文案应该怎么调整 |
|---|---|
| 肯定言语 | 文案权重 > 礼物本身。礼物可以简单但文案必须戳 |
| 优质时间 | 一次精心安排的约会/共处 > 实物 |
| 接受礼物 | 物品本身的质感、包装、仪式感更重要 |
| 服务行为 | 一次按摩 / 帮 TA 办成一件烦事 > 实物 |
| 身体接触 | 围巾 / 毛毯 / 丝巾等"可触碰"礼物加分 |

**2. 依恋类型**（隐藏维度，不让用户填）

- 类型：安全型 / 焦虑型 / 回避型 / 混乱型
- AI 从素材里隐式推断，用来调整礼物的"压迫感"和文案的"距离感"
- 不输出给用户、不让用户填

**3. MBTI**（可选填的兜底加分项）

- 用户在 Round 1 顺带提及就用，不知道跳过
- 绝不主动单独问

**明确不引入：** 任何外部书籍/教材知识库（包括《颂礼 361 问》或类似送礼指南）、OCEAN 五大人格、马斯洛需求层次、九型人格。

## 输出格式：5 字段方案 × 3 套

每套方案必须包含 **5 个字段**：

```
💎 方案一 · 细水长流款

🎁 礼物：[具体到能直接下单的礼物，含购买关键词]

✉️ 文案：[一句话或一小段送礼时说/写的话]

🕯️ 时机 & 呈现：[建议什么时候、用什么方式送出去]
   例："建议在她下班回家累的时候轻声说"
   例："建议写在便签上贴她电脑屏幕"

🗝️ 依据（仅供你参考）：[引用了哪条私密细节，证明 AI 不是凭空猜]
   例："基于你 2025-09-12 日记里提到她抱怨办公室味道"

💬 如果 TA 问"你怎么想到的"，你可以这样说：
   [一句让用户能"内化"成自己说法的话术]
   例："最近一直留意你的状态，发现你提过几次办公室那股味道。"
```

**5 个字段的功能分工：**

| 字段 | 功能 |
|---|---|
| 礼物 | 决定"送什么" |
| 文案 | 决定"说什么" |
| 时机 & 呈现 | 决定"什么时候 / 怎么送"——礼物只是 1/3，时机和呈现是另外 2/3 |
| 依据 | 让用户看到 AI 真懂、建立信任（仅用户内部使用） |
| 话术 | 让用户能"对外"使用，把 AI 洞察转化为自己的语言 |

**三套方案的差异化定位（必须明确不同）：**

- **细水长流款**：低调、日常、长期使用感（通常价位较低）
- **惊喜爆破款**：戏剧性、有记忆点、可能踩雷（通常价位较高）
- **安全稳妥款**：不出错、得体、有质感（中等价位）

→ 三套天然按价格梯度差异化，即使用户没明说预算也覆盖不同消费力。

### 🎯 确定性原则（产品核心承诺）

用户来用 skill 的目的，就是**得到一个确定性的礼物选择**。所以输出必须满足：

**1. 推荐度排序（必须有）**

3 套方案输出完后，AI 必须明确说：

> "我最推荐方案 X，因为 [具体理由，引用素材里的细节]。
>  如果你担心 [具体顾虑]，那就选方案 Y。
>  方案 Z 是兜底——简单不出错，但戳人程度有限。"

**绝不能**给 3 个平等方案让用户自己选——决策瘫痪是大忌，违背 skill 的核心承诺。

**2. 礼物字段的"可购买性"硬要求**

每个方案的"🎁 礼物"字段必须包含：

- **具体到型号 / 品牌 / 关键词**（用户能直接拿到淘宝/京东/Amazon/亚马逊日本 搜索）
- **参考价格区间**（如 "¥200-400"）
- **购买渠道建议**（淘宝？小红书种草？品牌官网？海淘？）
- **到货时间提示**（"次日达可" / "需预订 3 天" / "建议提前一周下单"）

**❌ 反例（绝对禁止）：**

> 礼物：一束尤加利配香薰

**✅ 正例：**

> 礼物：尤加利干花束（小红书搜"尤加利桉树叶"，¥80-150，顺丰次日达）+ Lumira 黑无花果香薰（天猫海外旗舰店，¥380，预计 5-7 天到货）

**3. 确定性 ≠ 全知**

AI 必须在关键节点承认不确定性，但**形式上仍是确定建议**：

> "方案 1 适合 TA 不抗拒香味的情况——如果你不确定 TA 对香味的接受度，那直接选方案 2。"

而**不能**说：

> "也许方案 1，可能方案 2，看你自己。" ← 模糊推卸，禁止。

## 错误使用反提醒（防止用户错用产品）

某些场景下，**送礼物可能是错的策略**。skill 必须识别这些场景并主动反提醒。

### 触发条件

Round 1 解析时识别以下关键词组合 → 标记为"危机场景"：

- 冷战 / 吵架 / 分手 / 道歉 / 我错了 / 对不起 / 她生气
- 出轨 / 信任危机 / 离婚 / 修复 / 挽回

### 反提醒文案模板（Round 3 定位确认时附加）

> "我注意到这是个『关系修复』场景。说几句真心话——
>
> **礼物只是辅助，不是道歉的替代品。** TA 真正需要的，可能不是一份礼物，而是：
> · 你认真承认错了什么（具体到事，不要泛泛而谈）
> · 你说清楚下次怎么不重蹈覆辙
> · 给 TA 情绪空间，不要急于求"原谅"
>
> 礼物可以是诚意的载体，但只在"你已经把上面三件事做了"之后才有用。
>
> 接下来我给你 3 套方案，会偏克制、低调，避免'用钱解决感情问题'的观感。"

### 危机场景下的礼物特征

- 偏小、偏私密、偏"她个人需要"，不要张扬
- 文案要素：承认 + 不辩解 + 给空间 + 不强求原谅
- 时机：永远在"先认真道歉之后"

---

## 内部质量保证：偷 SeedX 的「自评-修复」思想

不做多智能体（过度工程），只在 prompt 里加一段自评指令：

> "生成完 3 套方案后，自己评估每套：'这真的戳人吗？'
>  如果某一套显得 AI 味重 / 太空泛 / 没用上素材里的细节，
>  内部静默重写一次再输出给用户。用户只看到最终结果。"

零成本，但能大幅提升输出质量。

### 开场白要求（`prompts/greeting.md`）

必须满足：
- **温柔、共情、不油腻**——符合"礼说"品牌人格
- **明确告诉用户接下来要做什么**
- **附 3 个不同情绪基调示例**（喜庆 / 愧疚 / 心疼，覆盖不同关系角色）
- **不超过 8 行**

参考示例：

```
嗨～你来这里，说明心里有个 TA。

跟我说说你现在的处境吧——可以是任何关于 TA 和你的事。
你不用想得太完整，第一反应告诉我就行。

🌰 比如：
  · "下周是我老婆生日，刚搬完家她特别累，想给她个惊喜"
  · "和女朋友冷战三天，因为我忘了她妈手术那天，想道歉"
  · "她最近考研压力很大，我心疼她"

我会跟你聊几句，然后给你 3 套礼物 + 文案 + 怎么送的方案。
```

## 验证方式

**功能验证：**
1. 跑 4 个典型场景：生日（喜庆）/ 道歉（危机）/ 慰问（心疼）/ 无素材（兜底）
2. 每个场景三种素材模式（路径 / 粘贴 / 无素材）都跑一遍
3. 检查输出是否：
   - 真的引用了素材里的细节（不是泛泛而谈）
   - 三套方案有明显差异（不是换皮）
   - 没有 AI 味套话
   - 5 个字段（礼物/文案/时机/依据/话术）齐全
   - 危机场景有反提醒

**质量验证（关键）：** 让 2-3 个真实朋友试用（不是开发者），观察：
- 看到输出时的第一反应（"哇这个真戳" / "嗯还行吧"）
- 把 AI 给的话术念出来时会不会觉得别扭
- 三套方案中实际会用哪一套

**隐私验证：**
- 给 skill 一个含"前任名字"或敏感关键词的笔记目录，确认 skill 会问清楚过滤策略
- 确认无素材兜底时 AI 不会编造细节

**迭代验证：**
- 用户说"第二个不喜欢"，AI 能定向替换
- 用户说"整体太贵"，AI 能整组降级

**多语言验证：**
- 用英语 / 日语描述场景，确认 skill 用同语言回答
- README 三语版本互相对照
